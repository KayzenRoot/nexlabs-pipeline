# NexLabs Command Center — NLE-CC-PLAN-001
Estado: PROPOSED / PLANEJAMENTO. NLE-INT-PLAN-001 e NLE-INFRA-PLAN-001 ratificados pelo proprietário; demais decisões preservadas sem promoção automática. Nenhum serviço instalado, acesso concedido ou despesa realizada. Catálogos anteriores são entradas, não substituir.

## Objetivo e escopo
Interface privada responsiva para 105 agentes, 92 pacotes, 62 workflows e 1.110 atribuições, sem duplicar o plano de controle. Catálogo de 35 superfícies lógicas (2 nativas, 6 complementadas, 27 extensões de domínio propostas; não implicam 35 aplicações ou 27 plugins). Agrupar as extensões em módulos de uma única aplicação. Nomes e rotas NexLabs são propostas, não APIs existentes. Não prometer capacidades externas não qualificadas.

## Hierarquia de fontes
Checkpoint > ADRs > Scope > DoD > Architecture > Requirements; Git, código, testes e evidências prevalecem sobre memória. `source-lock.json` registra SHA256 das entradas locais; Context Lock Git fica pendente até bootstrap no repositório. Não modificar os catálogos. NLE-CC-PLAN-001 é candidato ao Source Pack, não o substitui.

## Arquitetura e decisão de integração
1. Paperclip é dono de agentes, hierarquia, tarefas, projetos, goals, runs, skills operacionais, custos registrados, rotinas e aprovações nativas. `GET /api/companies/{companyId}/dashboard` documentado e company-scoped. Não escrever diretamente nas tabelas internas. Usar links nativos e APIs documentadas, com IDs resolvidos no preflight; evitar iframes e CSS global que dependa de DOM interno.
2. Preferir um plugin local versionado com páginas/widgets/tabs e navegação quando o SDK alpha for qualificado. Instalação manual pelo proprietário, manifest mínimo, versões pinadas, read-back, desativação e regressão. Testar escopo de company, autorização de usuário, capacidades e upgrades. Não conceder acesso global ao plugin por conveniência. Se o plugin não atender UI/segurança/performance, usar SPA privada complementar com BFF na mesma rede WireGuard, links profundos para Paperclip, autenticação própria ou integração de sessão oficialmente suportada; nunca copiar cookies/tokens indiscriminadamente. Sem fork inicial. Nenhuma extensão de shell experimental exigida. Um único BFF modular se necessário, sem novo serviço por domínio.
3. NexLabs Enterprise API é proprietária de CRM, projeções de receitas, catálogo comercial/editorial, ledger de ações críticas, avaliações, conhecimento e telemetria normalizada. PostgreSQL com bancos/roles separados do Paperclip conforme NLE-INFRA-PLAN-001. GitHub é fonte de código/PR/CI; Cakto fonte de transações quando qualificada; provedores de ads fontes de métricas e estado; Netdata fonte de observabilidade; Intelligence Hub fonte de RAG/grafo/avaliações. Não criar integração se capacidade nativa ou existente qualificada já atende. Projeções somente leitura, reconciliáveis, não segunda fonte de verdade.
4. Browser recebe somente dados autorizados, sem tokens de provedores; BFF valida principal humano, company, tenant, projeto, escopo, finalidade, capacidade, versão de política. Se plugin operar com identidade de serviço, preservar identidade do solicitante e validar ACL independente, não confiar em company informado pelo browser. Autorização no servidor antes de query/cache/stream/export. Sem acesso direto a DB, Docker, SSH ou shell pelo navegador. Sem credenciais de trading real.
5. Mutação via gateway: request_id, idempotency key, actor, tenant, action, target, payload_hash, policy_version, expected_version, authorization/approval_id, expiry. Preparação -> revisão -> aprovação separada -> execução -> read-back -> reconciliação. Verificar novamente escopo, quota, hash, validade e versão na execução. Resultados incertos ficam RECONCILIATION; sem retry cego. Ledger de extensão referencia aprovação Paperclip quando aplicável; não considerar aprovação nativa suficiente para ampliar escopo. Emergência pausa novas ações; não prometer cancelar ação já enviada. Dados críticos de identidade, políticas e permissões protegidos fora do prompt. Nenhum agente autoaprova.
6. Usar HTTP com paginação; polling adaptativo inicial, SSE apenas se qualificado, reautenticação em reconexão; ocioso e background mobile reduzem polling. Cache privado chaveado por escopo e versão ACL; invalidar revogação. Nenhuma PII ou tokens em service worker, localStorage ou logs. Exports sob política; CSV seguro contra formula injection. CORS restritivo, CSRF para cookies, CSP, XSS e rate limit. Links externos allowlist. UI nunca é enforcement.

## Design system: OBSIDIAN / Neon Glass
- Fundo #080B12; painel sólido #111827; vidro #171F2E com alpha 0.90; borda #303D50; texto #F1F5F9; secundário #A9B7CB; verde-lima #B8F34A (ação principal), magenta #F472D0 (inteligência); azul #60A5FA informacional; âmbar #FBBF24; vermelho #F87171. Não usar status por cor apenas. Texto escuro #0B1119 sobre botão lima. Validar contraste sobre o fundo real inclusive transparência; WCAG 2.2 AA como alvo.
- Tipografia system UI (sem fontes remotas); 12/14/16/20/24/32 px, corpo 14–16, números tabulares; Lucide candidato já utilizado no Paperclip, qualificar licença/versão. Espaçamento 4/8/12/16/24/32. Raio 12–20 px. Sombra curta e borda iluminada discreta. Blur opcional 8–12 px somente em pequenas superfícies, fallback opaco.
- Efeito 3D: camadas CSS, perspectiva sutil em cards não críticos apenas desktop/pointer fino; nada de WebGL obrigatório, tilt em valores financeiros ou em botões de aprovação. Microinterações 120–220 ms, entrada 180–240 ms; reduced-motion desativa tilt, parallax e animações decorativas. Sem animações infinitas ou autoplay.
- Desktop >=1280: sidebar 240 px, header fixo lógico, grid 12 colunas, painel de detalhe opcional. Tablet 768–1279: sidebar compacta, grid 6 colunas. Mobile 320–767: coluna única/2 cards quando couber, bottom nav Início/ZEUS/Tarefas/Aprovações/Mais, drawer de módulos, filtros em sheet, tabelas em cards ou rolagem contida. Áreas de toque alvo 44x44 px. Graph/list toggle; lista é navegável por teclado. Sem scroll horizontal da página a 320 px. Safe area iOS, zoom 200%, foco visível, rotas de retorno. Navegação nativa Paperclip não será modificada sem qualificação.
- Componentes: metric card, status chip, source timestamp, freshness bar, trend line, data table, filters, kanban link, agent card, audit timeline, risk panel, approval dossier, empty/error/stale/loading/forbidden states, export dialog, chart accessible table. 3D é estética, não requisito para ações.

## Estados de dados e métricas
Todo indicador tem valor ou null, unidade, período, timezone, origem, as_of, status (LIVE/STALE/UNKNOWN/UNAVAILABLE/SIMULATED), versão de cálculo e escopo. N/A para dado desconhecido, não 0. Sem preencher dashboard com números fictícios. Catálogos planejados têm rótulo PLANEJADO e não equivalem a provisionamento. Em Paperclip `active` inclui idle; `running` é diferente. Custo registrado não equivale a custo total ou quota Plus. BRL/USD separados até conversão datada. Ações simuladas sempre identificadas e não somadas a receita real. CTR=cliques/impressões; CPA=gasto/conversões atribuídas; ROAS=receita atribuída/gasto; CAC=despesa aquisição/novos clientes; margem=receita líquida menos custos conforme ledger; denominador 0 => N/A; períodos e atribuição explícitos. Deduplicar webhooks e não somar conversões Meta e Google como clientes únicos. Trading: drawdown pico-a-vale, Sharpe com periodicidade e taxa livre de risco documentadas, slippage/fees; sem promessa de lucro.

## Performance e operação
Respeitar orçamento agregado 4,5 GiB candidato, concorrência LLM global 1, sem heartbeat inicialmente, no máximo 1 job pesado Windows. UI não chama modelo ao carregar tela; ZEUS usa fila. BFF e UI precisam caber no orçamento do Intelligence Hub/auxiliares ou substituir componente; se não couber, bloquear implantação e replanejar, sem ampliar recursos. UI estática compilada, lazy loading por módulo, listas virtualizadas, graph limitado inicialmente a 100 nós com expansão autorizada, sem carregar 105 agentes e todos os logs de uma vez. Metas de qualificação propostas: LCP <=2,5 s, INP <=200 ms, CLS <=0,1 (p75 em perfil documentado), GET dashboard p95 <=800 ms quente em rede privada, sem regressão dos serviços existentes, bundle inicial comprimido <=300 KiB para shell complementar, não atribuir orçamento do shell a upstream. Testar desktop, Windows, Safari/iOS real, 320/390/768/1440, rede degradada, worker offline; em caso de falha upstream mostrar última leitura datada e desabilitar mutações incertas. Logs redigidos. Backup RPO 24h / RTO 4h condicionado a infraestrutura substituta, conforme plano anterior. Sem novas cobranças; bloquear recursos não qualificados, inclusive anúncios pagos.
