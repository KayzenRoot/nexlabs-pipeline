# Database / Data Model (logical, proposed)
Não migrar no bootstrap. Preservar DB Paperclip e DB NexLabs separados; IDs upstream referenciados, não copiados como autoridade. Entidades NexLabs: tenant, project, principal, grant, policy_version, task_ref, event/outbox, job_lease/fence, effect_intent, approval, audit_event, agent_binding, skill_artifact/lock, workflow_version, source/document/chunk/embedding, claim, graph_node/edge, memory_candidate, learning_proposal/evaluation, CRM organization/contact/opportunity/proposal, product/offer/order_ref, campaign_snapshot, finance_entry/reconciliation, simulation_run/fill, metric_snapshot. Chaves tenant/project onde aplicável; UUID ou IDs estáveis do catálogo; timestamps UTC, datas locais só para exibição; índices e constraints de unicidade por escopo, idempotência, validade de versão; valores monetários decimal + moeda, real/simulado separados inclusive agregações. Proveniência, hashes, retenção, deletion tombstone e versionamento. RLS em cada tabela sensível; testes negativos inclusive grafo/caches; serviços sem bypass. Migration/rollback e constraints só em WO autorizada, revisar contratos de sources/Intelligence.
