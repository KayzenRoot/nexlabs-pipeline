# Governance
Fluxo: ANALYZE → SOURCE CHECK → NEXT NECESSARY INCREMENT → WORK ORDER → CONTEXT LOCK → PREFLIGHT → EXECUTOR → TESTS/EVIDENCE → PR → AUDIT → APPROVED/CORRECTION REQUIRED/BLOCKED → CHECKPOINT DELTA → MERGE → NEXT. Branch `work/nle-<id>`; mesmo ID em PR, testes, logs e correções CD-xx. Um incremento ativo; não avançar com falha HIGH/CRITICAL ou bloqueio. Executor inspeciona repo, implementa apenas WO, testa, corrige, commit/push/PR; review pt-BR. Auditor separado do executor, sem self-approval. Atualizar checkpoint e todas fontes afetadas após aprovação objetiva e antes do merge conforme gates; conferir merge SHA e estado final. No force-push, bypass, rewrite ou ação destrutiva.
GitHub: alvo privado, main protegida, PR obrigatório, squash only, checks obrigatórios reais, sem force-push/delete, permissões mínimas, ações pinadas por SHA, workflows sem secrets em PR, sem `pull_request_target` para código não confiável. Confirmar disponibilidade por plano, billing e franquia Actions; se proteção/checks indisponíveis, documentar BLOCKED, não contratar ou simular enforcement. Sem revisores externos pagos; independência humana/agente separado e evidência, sem fabricar aprovação GitHub. Verificar e-mail/identidade do GitHub sem alterações de conta não autorizadas. Rulesets e settings requerem read-back. Só criar repositório privado se ausência confirmada e identidade/namespace autorizados; 404 sozinho é ambíguo. Nunca criar em namespace alternativo. Se repo vazio, inicialização mínima na default branch só quando realmente necessária para PR, documentar exceção e aprovação/limites; Source Pack em PR separada, não assumir proteção inexistente. Se GitHub não permitir, BLOCKED.
